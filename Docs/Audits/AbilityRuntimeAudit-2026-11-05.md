# Ability 0.2.1 正确性与性能复查

对象是独立技能包 Assets/Scripts/Ability，排除 Framework。基线是本轮修改前的远端提交 38d27c5e5ee654901a402d078d6fbf84d38c5dc6；新性能工具在独立基线目录编译，避免把并行修改混入比较。本轮发现并修复支持路径的缺陷，没有将未实现的 Dota 规则包装成已完成能力。

## 已确认并修复

| 范围 | 触发与原结果 | 修复后的行为与证据 |
| --- | --- | --- |
| 施法计时 | 长帧中前摇结束，冷却/充能漏扣剩余时间；回调重开计时器又吃旧帧或被旧补偿覆盖 | 区分计时器代际，只推进正确余量；帧起值类型快照阻止A回调启动/重置的B施法和计时器追扣旧帧；17项施法新回归包含恢复预算、过滤/参数/观察者异常、中断清理、0级固有效果清理与CastId |
| 攻击与治疗 | 提交通知抛错后攻击卡在Resolving；AttackStart异常留下pending；治疗事实事件丢失 | HP结果返回后先冻结已提交事实；通知失败仍完成合规收尾，再聚合异常；14项战斗新回归 |
| 来源边界 | 已注销/同ID旧实体、跨引擎/旧战斗Ability被接受；factory重入可泄露未登记来源或重复同名技能 | 验证引擎、出生代际、曾登记及Owner归属；factory后复查；保留同代已移除技能、死亡但未注销来源及null环境来源 |
| 对象与表现 | 表现回调让目标死亡后仍命中；NaN/Infinity坐标污染；Stop抛错后到期对象残留 | 命中前复验、拒绝非有限位置、异常后仍解除所有权；含来源与快照共17项对象新回归 |
| 运行快照 | 外部getter增删触发集合枚举异常；自移除Modifier被记录、后续条目遗漏 | 固定成员快照、检查代际与登记状态；不把新加入对象追进本次快照 |
| 配置大图 | 合法1000节点链在64KiB工作线程触发StackOverflow；立即创建、Special和legacy图路径递归 | 改显式栈，不向运行时引入编辑器256作者预算；13项配置新回归覆盖5000层六类引用、发布/环/来源/特殊值/原子性 |
| 空间查询 | 粗候选超出半径仍被接受，同ID多wrapper重复；query回调清理后提交旧候选 | 精确三维半径、有限坐标、实体去重、代际与预算失败时不提交；12项空间查询回归 |
| 查询预算 | 大范围纯静态筛选累计HasState调用，合法500/1000目标被2048预算截断 | 静态内置读不算脚本操作，深度仍检查，自定义状态仍计预算；1000目标在64操作预算完成，递归自定义状态仍中止 |
| 事件 | 同事件配置监听每次扫描全世界；仅属性脚本继承空OnEvent仍耗预算；Related Respawn不触发 | 按事件+实体候选索引，保留Global/custom注册顺序；明确空回调可跳过；21项事件关系/重入/顺序/清理/Respawn新回归 |

事件索引只缓存订阅与成员关系，不缓存动态状态、属性值或伤害结果。自定义覆盖的全局事件回调仍全部投递；反射信息缺失或不明确时保守保留投递。真实 IL2CPP 元数据行为仍需目标构建验证。

精确HP接口有明确边界：若项目适配器在修改HP后自行抛错且不返回结果，核心无法可靠推断提交量，不能用前后HP差伪造事实。适配器应准确返回提交结果，将项目通知与该返回值隔离。

## 可重复性能测量

新工具位于 [CombatPerformance](../../Tools/AbilityVerification/CombatPerformance/README.md)，保留baseline/current原始采样。使用.NET 8 Release、相同硬件/负载/JIT配置；每轮10次预热、120个逐批次样本，共3轮，记录P50/P95/P99/max、当前线程分配、GC、实际HP/事件数量、预算中止和清理余数。

每个样本是固定操作批次，不等于Unity整帧。伤害批不含另一次Engine.Update；新弹道与到期批含Update。单位HP在计时前复位，避免死亡或满血减少实际工作。查询候选、反伤和吸血也有结果断言。

1000单位、每单位3个基础Modifier，取三轮P50的中位数：

| 固定批次 | 基线 → 当前CPU | 基线 → 当前托管分配 |
| --- | ---: | ---: |
| 500次伤害+反伤+吸血 | 18.101 → **2.498 ms** | 2,832,000 → 2,544,000 B |
| 2000个重复候选的宽查询 | 3.388 → **0.637 ms** | 0 → 0 B |
| 500次普通伤害 | 0.867 → 0.974 ms | 936,000 → 792,000 B |
| 500个新追踪弹命中 | 2.183 → 2.631 ms | 1,888,024 → 1,744,024 B |
| 500个新直线弹命中 | 2.960 → 3.366 ms | 1,992,024 → 1,848,024 B |
| 1000个Modifier添加与到期 | 8.095 → 8.207 ms | 1,144,024 → 1,144,024 B |

普通伤害和新弹道路径CPU没有改善；归属/有效性重检增加工作，实际差异也受共享主机干扰。不能宣称所有路径都加速。事件热点改善约7.2倍，但GC仍明显；例如500条带proc伤害链仍分配约2.54MB，不能判为目标设备性能已达标。

当前 **81/81** 场景有效，设置与运行预算中止均为0，清理对象余数均为0。基线只有69/81有效：9条粗候选wrapper场景结果错误、3条1000单位动态属性场景设置中止。失败行保留，不能用于等工作提速比较。曾在开发中的宽查询预算误截断也已修复，没有把它包装成快速结果。

便携Unity ListPool替身会分配，动作密集路径的部分分配在真实Unity中可能下降；仍有事件/结果隔离对象需要分配。真实物理、Transform、资源、表现、Mono/IL2CPP和目标设备长时间GC/内存稳定性尚未测量。
