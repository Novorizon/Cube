# Ability Studio · Odin

面向 Unity 2022.3 与 Odin Inspector 3.x 的可选技能 JSON 编辑器。入口是 **Tools → Ability → Skill Studio**。本包只在 Editor 编译，运行时 Game.Ability 不依赖 UnityEditor 或 Odin。

## 安装

1. 项目先安装 Ability Runtime 0.2.0。已有 Assets/Scripts/Ability 时保留该安装方式，不要再编译第二份同名程序集。
2. 安装项目已有授权的 Odin Inspector 3.x；本交付不包含 Sirenix 二进制，也不要求 Odin Validator。
3. 解压编辑器 ZIP，将 com.novorizon.ability.editor.odin 放入项目 Packages 目录，或通过 Package Manager 的 Add package from disk 选择其中 package.json。
4. 等待脚本编译，打开工作台。没有 Odin 或 ODIN_INSPECTOR 标记尚未生效时，入口显示安装提示，不影响运行时包。

包的 asmdef 引用 Game.Ability，Odin 依赖使用其默认自动引用的 Editor DLL。为兼容运行时位于 Assets 的项目，本包没有声明会触发远端注册表解析的 Runtime UPM 版本依赖；请按上述顺序安装。

## 界面与操作

三栏工作区支持 Unity 深色／浅色主题，使用统一的青绿强调色、卡片分组、紧凑状态标签和中文字段：

- 左侧是文件与条目列表，按技能／Modifier／弹道分类，支持名称、ID 和显示名搜索。引用是链接，不无限递归展开。
- 中间是配置、JSON 预览和直接引用三个视图。配置包括枚举／flags、常量／等级表、Special、动作、光环、事件、充能与表现标识。
- 右侧是生产诊断和隔离试运行。错误支持跳到文件和能识别的定义；没有可靠 JSON span 时不会伪造精确行列。

使用“选择技能库”指定只包含技能 JSON 的目录。仓库样例在 Data/AbilityJsonSources/Heroes，7 位英雄／14 个技能可作为起点；该目录是可选业务数据，不是包依赖。目录中的每个 .json 都视为技能文件，不要选择含其它产品 JSON 的项目根目录。

可新建文件，添加、复制、删除技能／效果／弹道，调整动作顺序，选择定义引用。复制条目会生成新 Name/ID，并保留指向现有依赖的引用；它不执行依赖闭包复制或全工程重命名。顶层定义中出现 null 时可用“移除空条目”修复，并可撤销。

等级值未配置时保留运行时默认；动作 duration 未配置时继承 Modifier 定义，显式 0 则为永久。表单只在真实交互时修改 DTO，展开折叠不会把缺省值改成显式值。切换动作类型会保留隐藏字段，生产校验仍会指出不合法组合。

## 校验与试运行

静态校验调用生产 reader、Provider 和 Registry，检查字段、数值、ID、引用、立即创建环与不支持机制；源文件出现未知字段、未来 schema 或非法 JSON 时保持原文只读。

调用递归生产图校验前，编辑器先执行非递归引用预检。默认作者复杂度预算为 256：按强连通组凝聚后的路径计算保守上界，超过时显示诊断并阻止保存／试运行。它不是“最多嵌套 256 个 Buff”的运行承诺；1000 个互不引用的 Modifier 不会因此被拒绝，小型事件环也不会被直接认定非法。

运行预算与静态引用层数是两回事。默认运行调用深度为 64，一次执行链最多 2048 次操作；它们不等于允许 64 个 Modifier 嵌套。试运行可调整预算、等级、目标数和模拟时长，捕获 ExecutionAborted 原始消息并显示事件轨迹、实际伤害／治疗和清理后对象数。

试运行使用独立引擎、单位、资源、世界和表现适配器，不访问正在战斗的场景实例，不自动发现或执行业务脚本。requiresCustomScript 定义会明确报告缺少测试适配器。每条退出路径清理临时对象；尚有前摇、引导或弹道时会提示时间窗口未覆盖完毕。通过一次场景不代表所有事件、目标数量和自定义代码路径都已验证。

## Undo、保存与草稿

- Ctrl/Cmd + S 保存当前文件；Ctrl/Cmd + Shift + S 尝试保存全部草稿。Unity Undo/Redo 记录编辑 JSON 快照，保存后撤销会重新显示未保存状态。
- 新建文件先作为内存草稿，明确保存后才写磁盘。保存复用生产校验，检查原始文件字节 SHA-256、只读状态和引用文件是否变化；外部修改时保留草稿并阻止覆盖。
- 单文件使用同目录临时文件、复读和替换提交；失败保留原文。保存还按其它文件的磁盘状态验证，避免落盘依赖尚未保存的草稿。
- 切换技能库和刷新会先处理未保存草稿。域重载和窗口关闭时使用 Unity SessionState 保留当前编辑器会话的恢复信息；磁盘变化或恢复失败会保留原草稿并提供另存副本。
- SessionState 不是持久备份，不能保证 Unity 进程异常退出或系统断电后的恢复。重要更改应保存并纳入项目版本管理。

当前没有跨文件原子重命名／多文件重构事务。相互依赖的名称修改可能无法逐文件提交；应通过新增定义、切换引用、再移除旧定义分步迁移。工作区服务支持项目显式传入只读 Provider 索引，当前 UI 不自动搜索或执行项目 Provider。

## 验证边界

Tools/AbilityVerification/Editor 提供 codec／工作区／沙盒源码检查。UI 源码额外引用仓库实际 Odin DLL，并对照 Unity 2022.3 API 做兼容编译；Unity 类型使用验证替身。Odin 二进制只作为本机验证引用，不随源码或归档分发。

尚未在真实 Unity 中运行窗口、验证实际视觉、鼠标键盘交互、Undo/域重载、资源与原生文件替换行为。导入后应先在测试数据副本上运行这些验收，再用于正式配置。完整步骤见交付工程中的 Docs/AbilityEditorGuide.md。

## 配套运行时

0.1.1-preview.1 的 UPM 清单显式依赖 com.novorizon.ability 0.2.2-preview.1。先通过 Git URL 或 tgz 安装 Runtime，再安装编辑器；Odin Inspector 3.x 由项目单独安装，不随包分发。Runtime 的清单和程序集均不反向引用编辑器。
